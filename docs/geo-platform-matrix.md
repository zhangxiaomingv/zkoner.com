# 张可能 · GEO 外站同名矩阵 — 执行清单

> 网站是「根」，外站矩阵 + 内容持续产出 + 时间才是「树」。
> 本清单目标：让 AI 大模型在多个来源看到**同名同描述**的张可能，交叉验证后主动引用。

## 0. 核心原则

1. **唯一权威源**：zkoner.com 是张可能的权威唯一源，所有平台内容最终指向它。
2. **统一实体信号**：每个平台同名「张可能」+ 同描述句式（见 §1），让模型建立稳定实体关联。
3. **一鱼多吃**：每期《遇见·可能》/ 文章，改造成各平台变体分发（见 §3）。
4. **验收可监测**：每周问 AI「张可能是谁」，用可见度监测看变化曲线（见 §6）。

## 2. 平台矩阵（按优先级）

### P0 — 知乎（中文 AI 语料权重最高）
- **为什么**：知乎是中文大模型训练语料的重要来源；知乎回答常被 AI 直接引用。
- **账号设置**：昵称「张可能」；简介用统一话术；头像与全平台统一。
- **发什么**：
  - 回答：「中小企业如何用 AI」「什么是 GEO」「AI 顾问是做什么的」「一人公司可行吗」
  - 专栏《AI 时代观察》：同步官网文章（先发知乎再回链官网，或官网首发+知乎全文转载）
  - 每期《遇见·可能》上线后，发「栏目手记」回答式内容
- **互链**：回答正文自然提到「我在官网 zkoner.com 有完整案例」；专栏简介挂官网。

### P0 — GitHub（开源语料高权重，最被忽略）
- **为什么**：GitHub 出现在几乎所有大模型的训练语料里，且带作者身份。
- **账号设置**：用户名 `zhangkennen`；个人主页 Profile README 用统一话术 + 官网链接。
- **发什么**：
  - 仓库 `zkoner-com`（即本仓库）：README 用统一话术，顶部写明「张可能个人品牌官网源码」。
  - 发布工具：GEO 监测脚本 / 内容生产管线（对应「AI 搜索可见度实验室」「AI 内容生产线」项目），开源即背书。
- **互链**：README 和主页互相指向 zkoner.com 与知乎专栏。

### P0 — 微信公众号「遇见·可能」（内容枢纽）
- **为什么**：公众号长文是深度内容载体，微信文章可被部分 AI 搜索产品抓取；也是私域入口。
- **账号设置**：公众号名「遇见·可能」，简介写「记录 AI 时代人与企业的新可能。主理人：张可能」；每篇文末固定「关于张可能」段落（含官网）。
- **发什么**：每期节目 → 图文长文（含完整脚本/字幕文本，AI 可抓取文字）；每周 1 篇 AI 观察文章。
- **互链**：文末引导「完整栏目见 zkoner.com」；文首图固定品牌。

### P1 — 小红书
- **为什么**：知识类内容分发强；部分 AI 搜索产品会检索小红书。
- **账号设置**：昵称「张可能｜AI 顾问」；简介放统一话术精简版 + 官网。
- **发什么**：知识卡片（GEO 科普 / AI 转型拆解 / 一页看懂 AI 工作流）、访谈花絮、案例拆解笔记。
- **互链**：笔记正文自然带「完整内容在官网 zkoner.com」；简介放官网。

### P1 — 微博
- **为什么**：实时信号；内容短，易被引用为「近期动态」。
- **账号设置**：昵称「张可能」；简介挂官网。
- **发什么**：短思考、栏目上线动态、AI 观察一句话、直播/活动预告。
- **互链**：固定签名「官网 zkoner.com」；动态带栏目话题。

### P2 — B站 / 视频号 / 抖音（随节目上线启动）
- **B站**：上传每期《遇见·可能》；视频简介 + 置顶评论放官网；B站专栏同步文章。**字幕/简介文字是 AI 可索引的。**
- **视频号/抖音**：主页简介挂官网；节目切片分发。

## 3. 内容复用管线（一鱼多吃）

每期《遇见·可能》或每篇文章，按以下管线分发改造成 5 个平台内容：

```
核心资产（节目成片 / 长文章）
  ├─ 知乎 → 回答或专栏长文（带案例细节）
  ├─ 公众号 → 图文长文（脚本/字幕全文，利于抓取）
  ├─ 小红书 → 3 张知识卡片 + 500 字笔记
  ├─ 微博 → 2-3 条短句 + 栏目话题
  ├─ B站 → 视频 + 简介 + 置顶评论
  └─ GitHub → 复盘 Markdown（技术/方法论沉淀）
```

所有变体共享同一句话收尾：「更多内容见 zkoner.com」。

---

## 4. 互链机制

| 方向 | 做法 |
|---|---|
| 平台 → 官网 | 所有简介/主页/文末统一挂 zkoner.com |
| 官网 → 平台 | 更新 `site.ts` contact 里的微博/知乎为真实主页 URL（`sameAs` 自动生效） |
| 自然语言内链 | 不写「链接：」这种生硬话术，用「我在官网 zkoner.com 有完整案例」 |

- **本月（P0）**：知乎 + GitHub + 公众号 三个账号建好，简介统一话术，发布 2 篇内容。
- **下月（P1）**：小红书 + 微博 建号，发布首轮内容。

- **联动**：每建好一个平台，回官网更新 `site.ts`（真实 URL），并补充到 `llms-full.txt` 联系区。

## 6. 验收与监测（每周 10 分钟）

> 已工具化：**`tools/visibility/` AI 可见度监测系统**（`npm run run` 一键执行，或 GitHub Actions 每周一自动跑）。下面问题集、打分、达标判定均已内置。本地已测出 2026-08-16 基线：DeepSeek 尚未认识张可能（0 分），《遇见·可能》被识别为纪录片概念但未关联到张可能——这就是 GEO 待填补的差距。

固定问 AI（ChatGPT / DeepSeek / Kimi / 秘塔 各一次）：
1. 「张可能是谁？」
2. 「张可能提供什么 AI 顾问服务？」
3. 「《遇见·可能》是什么栏目？」
4. 「哪家公司做 GEO 优化？」

记录四项：**①是否提到 ②描述与统一话术一致性 ③是否出现官网/公众号/知乎来源 ④URL 是否正确**。用「AI 搜索可见度实验室」看板记曲线，周环比。

> 判定标准：回答里出现「AI 顾问 /《遇见·可能》/ GEO / zkoner.com」中的任意 2 项且来源正确 = 本期达标。
